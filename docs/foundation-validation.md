# PR14 audit ledger draft

Prepared 23 September 2026 from `docs/ui-ux-audit-2026-09-13.md`, `foundation/docs/foundation-roadmap.md`, the integrated foundation through PR10, and the PR11–13 worker trees and evidence under `.worktrees/`.

This is a working ledger, not release sign-off. The integrated foundation is currently at PR10 (`d1dd7b2`). PR11 (discovery), PR12 (pipeline), and PR13 (cleanup) still have worker changes awaiting ordered integration and final combined checks. Statuses for those layers are provisional. The early per-layer tests and independent browser reviews are evidence for the changes they cover; they do not replace the final integrated run.

Status terms: **Verified** means a relevant regression check or independent review is recorded; **pending** means the worker change or its integrated validation is not complete; **manual gap** means the audit calls for evidence not supplied by the current automated tests. Browser automation with synthetic keyboard/pointer events is not evidence from a real device, screen reader, or soft keyboard.

## PR14 release checks to close

1. Integrate PR11–13 in order; do not use worker-only test passes as final branch validation. Perform a fresh frozen install and final production build, then run `pnpm test:routes`, Pagefind inventory/search tests, lint, format checks, and the full browser suite. 2. The validation branch now defines Chromium, Firefox, and WebKit projects for both production and fixture suites, and CI installs all three browsers. Verify test discovery now and run the complete integrated suite in each engine; justify any narrowly scoped engine exclusions rather than disabling tests preemptively.
3. Inspect final light/dark screenshots at 390, 768, and 1280 px for the audited home, blog, article, notes/tag, About, contact, and gallery surfaces. Include 320 px for share controls and scientific images. Check browser zoom at 200%; verify layout reflow and operation, not just a narrower viewport.
4. Use the deployment preview attached to the final Workers build check run. The PR10 precedent is the `Workers Builds` check-run `output.summary` returned by `gh api repos/romaingrx/romaingrx.com/commits/<sha>/check-runs`. Confirm redirects (301 plus exact `Location`), unknown-path 404 status/body, sitemap/robots and Pagefind assets, live Giscus theme updates, portrait image bytes, and OG/RSS responses on that deployed URL. Do not classify preview validation as unavailable before querying the check-run summary.
5. Verify the first dark frame on a fresh production navigation under network throttling, since the existing theme tests check state changes rather than the no-flash loading path. Distinguish fixture-mocked Giscus theme tests from the live external embed.
6. `tests/browser/release.spec.ts` adds two narrow content integrity checks: note share/copy URLs equal the canonical note URL, and generated production HTML has no empty `href` anchors. Run both after PR11–13 integration and review any exception instead of rewriting legitimate targets mechanically.
7. Perform a keyboard pass through global navigation, search, Contents/citations, dialogs/gallery, controls, and scientific sliders. Verify focus visibility, native Enter/Space, Escape where appropriate, and reduced motion. Record actual screen-reader, physical touch, and soft-keyboard work only if those facilities/devices are used; otherwise mark each as unverified. No such device, VoiceOver, or soft-keyboard validation is claimed by this draft.
8. The validation branch adds a failure-trace upload step to `.github/workflows/ci.yml`. Playwright uses `trace: 'retain-on-failure'`; historical PR06/PR08 CI logs show `test-results/**/trace.zip`; and the pinned `actions/upload-artifact` v7.0.1 step retains matching traces for seven days. Confirm artifact upload on the next CI run.

CI trace step, after `Browser smoke tests`:

```yaml
- name: Upload Playwright traces
  if: ${{ !cancelled() }}
  uses: actions/upload-artifact@043fb46d1a93c77aae656e7c1c64a875d1fc6a0a # v7.0.1
  with:
    name: playwright-traces-${{ github.run_id }}-${{ github.run_attempt }}
    path: test-results/**/trace.zip
    if-no-files-found: ignore
    retention-days: 7
```

The PR06 and PR08 CI failure logs demonstrate the generated trace path and local `playwright show-trace` instructions. The action is pinned to the full commit SHA for the official `actions/upload-artifact` v7.0.1 release; its official README documents the `path`, no-files behavior, and 1–90 day retention input ([v7.0.1 README](https://github.com/actions/upload-artifact/blob/v7.0.1/README.md), [verified release commit](https://github.com/actions/upload-artifact/commit/043fb46d1a93c77aae656e7c1c64a875d1fc6a0a)). This path uploads only trace archives generated for failures, uses a unique artifact name across reruns, tolerates successful runs with no traces, and retains them for seven days. The validation branch contains this change; a successful workflow artifact has not yet been observed.
